# Test Stack

## Browser recovery

- **Runner:** `@playwright/test` 1.64.1, pinned by `package-lock.json`; Chromium is the only configured browser.
- **Command:** `npm run test:e2e` runs `playwright test` against `tests/e2e/` with one worker.
- **Owned preview:** `playwright.config.ts` checks that the selected port is free, then runs `npm run build && npm run preview -- --host 127.0.0.1 --port <port>`. The default port is 4321; set `E2E_PORT` to override it. Playwright refuses to reuse an existing server and stops its preview after the suite.
- **Browser installation:** `npx playwright install chromium` locally; CI uses `npx playwright install --with-deps chromium`.
- **Authentication:** The setup project validates that app credentials and `supabase status -o env` point to the same local Supabase instance. It creates one confirmed, generated account with a private provisioning key, signs in through the real UI, and saves browser state under ignored `playwright/.auth/`. Each test context obtains a fresh session through the app sign-in endpoint. Privileged access is limited to account creation and teardown deletion.
- **Fixtures:** Tests create, read and delete spools and prints through authenticated app APIs. Unique labels and returned IDs are written to a private fixture ledger. Settings-changing browser tests write the original percentage to that ledger before the first mutation; cleanup reads the current settings version, restores through the real API, rereads to verify, and retains a failed marker. Pending markers are recovered before another test or retry. Product and settings cleanup are both attempted if either fails. The teardown project deletes the generated account. Provisioning never resets the database.
- **Settings coverage:** `tests/e2e/account-settings.spec.ts` covers saved display, 0%/100% boundaries, visible validation, pending-save disabling, persistence, version conflicts, and a committed save with a masked acknowledgement followed by failed and successful reads. Cross-tab tests exercise changed-margin best-fit/manual recovery, manual-choice fallback, same-amount 10%→9%, change-away-and-back, obsolete previews, and failed preview recovery. `tests/e2e/reservation-recovery.spec.ts` proves a settings save leaves an existing 88 g reservation and its stock contribution unchanged.
- **Diagnostics:** Screenshots are captured only on failure; traces are recorded on the first retry. The HTML report is written to ignored `playwright-report/`; results and auth artifacts are ignored and are not uploaded by CI.
- **CI:** The local Supabase/Mailpit job installs Chromium and runs the browser suite after local credentials are configured, before its existing smoke preview starts. The browser suite is separate from `verify:deploy` and requires local Supabase.
- **HTTP smoke:** `npm run smoke` runs `scripts/account-settings-smoke.mjs` after the existing default-margin reservation scenario. It uses the existing Account A/Account B jars and scenario/cleanup deadlines to verify protected responses, settings isolation, direct-write denial, preserved 88 g reservations, new 84 g best-fit/manual reservations at 5%, fresh-login persistence, and direct RPC witness handling. It restores Account A's original setting with the latest version and cleans only its generated fixtures.
- **Local prerequisites:** Start local Supabase with migrations applied and Mailpit available at `http://127.0.0.1:54324`; configure `SUPABASE_URL` and the local anon/publishable `SUPABASE_KEY` in the environment, `.dev.vars`, or `.env`. The smoke accepts confirmation links only from the configured `BASE_URL` or local Supabase `auth.site_url`, then replays their path and query through `BASE_URL`. Run smoke against the production preview with `BASE_URL` set when it is not `http://localhost:4321`.
- **Evidence boundary:** Browser HTTP interception simulates failed or unreadable acknowledgements. Forward-then-mask scenarios verify persisted writes through a separate real API read; they do not demonstrate provider outages. Remote CI remains unobserved until a workflow run is inspected.
