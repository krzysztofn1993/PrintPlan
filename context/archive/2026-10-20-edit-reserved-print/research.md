## Research Question

What currently prevents the S-05 reserved-print editing flow, which existing contracts must recalculation preserve, and what evidence and decisions does `/10x-plan edit-reserved-print` need?

The supplied change ID had no active or archived change folder at discovery. Scope comes from [S-05, roadmap:160](../../foundation/roadmap.md#L160) and its referenced PRD requirements. This research creates the active change identity and this document. It does not change the roadmap or approve implementation.

## Summary

- **S-05 is not implemented in the inspected update path.** The form locks material, colour and required grams for reserved prints. The database rejects changes to canonical matching requirements or grams, while allowing edits that preserve those values. [PrintForm.tsx:248](../../../src/components/prints/PrintForm.tsx#L248), [current update_print:70](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L70).
- **The target behavior is settled:** use the current account margin; retain an eligible manually selected spool, otherwise attempt best-fit; if no spool fits, commit the edited print and release its old reservation, with insufficient-material feedback. Release/replacement must be atomic. [PRD:87](../../foundation/prd.md#L87), [PRD:92](../../foundation/prd.md#L92), [PRD:119](../../foundation/prd.md#L119), [roadmap:169](../../foundation/roadmap.md#L169).
- **Persisted selection provenance and owner locking already exist.** Recalculation can read `selection_mode` from the reservation rather than infer manual intent from the selected spool. Its transaction must account for the edited print's own held grams and preserve request evidence used by release, replay and settlement. [reservation schema:7](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L7), [mutex:55](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L55), [release:313](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L313), [settlement:370](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L370).
- **The update result needs a deliberate outcome/recovery contract.** Today the helper rereads the print after the RPC and the UI announces that it was saved; this path has no saved edit receipt or explanation of why a reservation disappeared. Settlement supplies an existing example of separating a committed receipt from subsequent current-state reads. [prints.ts:193](../../../src/lib/prints.ts#L193), [PrintList.tsx:756](../../../src/components/prints/PrintList.tsx#L756), [settlements.ts:46](../../../src/lib/settlements.ts#L46), [PrintList.tsx:266](../../../src/components/prints/PrintList.tsx#L266).

## Detailed Findings

### Product scope and terminology

The PRD supplies the terms planned print, spool, reservation, recorded stock, reserved grams, available grams and account safety margin. The existing DTOs expose `requiredGrams` for print requirements and `recordedGrams`, `reservedGrams`, `availableGrams` for stock. No domain glossary exists in the inspected `context/` tree. Preserve these meanings during the handoff. [PRD:82](../../foundation/prd.md#L82), [PRD:115](../../foundation/prd.md#L115), [prints.ts:29](../../../src/lib/prints.ts#L29), [spools.ts](../../../src/lib/spools.ts).

The account margin accepts whole percentages from 0 through 100; reserved grams are rounded upward. Best-fit ranks eligible spools by least stock remaining after this reservation, then earlier spool creation, then ascending identifier. Settlement cancels newest reservations first using reservation creation time descending and identifier descending. These are existing product policies, not choices for S-05 to reopen. [PRD:121](../../foundation/prd.md#L121).

An insufficient-material result after a valid reserved-print edit is a **successful saved edit with no reservation**, rather than the rejection used for an unsuccessful initial reservation. An unreserved print's ordinary edit remains the S-02 baseline; S-05's named trigger is editing a reserved print. Completed prints remain protected by the current `print_settled` guard. [PRD:87](../../foundation/prd.md#L87), [roadmap:126](../../foundation/roadmap.md#L126), [roadmap:160](../../foundation/roadmap.md#L160), [update_print:78](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L78).

### Database baseline and atomicity

The current `update_print` definition comes from the settlement migration. It derives the owner from `auth.uid()`, acquires the owner's mutation mutex, locks the owned print, rejects settled or stale-version edits, and compares normalized material, colour identity and required grams before applying the edit. A name change, or a colour spelling change preserving its normalized key, passes this database guard without resizing the reservation. The browser currently exposes the name change. [update_print:45](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L45), [guard:85](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L85), [PrintForm.tsx:313](../../../src/components/prints/PrintForm.tsx#L313).

Normalization belongs to the database trigger: shared whitespace collapse, uppercase material with ICU root collation, and case-insensitive generated colour identity. On a print SQL update the trigger increments its version, preserves its identity and creation time, and updates its modification time. Even reservation code's `SET name = name` advances the version. Recalculation must consider its complete update sequence when defining the saved version. [print schema:20](../../../supabase/migrations/20261012000000_create_prints.sql#L20), [normalization/version trigger:38](../../../supabase/migrations/20261012000000_create_prints.sql#L38), [reserve version update:233](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L233).

The owner mutex provides the existing serialization boundary for print/spool CRUD, reserve, release, margin saving and settlement. Application roles have direct SELECT access to the product tables after the reservation migration revokes their direct mutation grants. The inspected RPCs use explicit owner predicates and protected function execution. A recalculation path must join this boundary before reading the state it will change. [mutex:55](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L55), [spool mutations:118](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L118), [privileges:333](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L333), [settings:73](../../../supabase/migrations/20261017000000_account_safety_margin.sql#L73), [reserve:113](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L113), [settlement:324](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L324).

**Inference from those contracts:** a browser sequence of release, edit and reserve would expose intermediate committed states and cannot meet S-05's atomic replacement requirement. The existing initial-reservation RPC also raises `insufficient_material` when no candidate fits, whereas S-05 requires the valid edit to commit unreserved. Planning needs an atomic database operation with explicit no-fit success semantics. [roadmap:169](../../foundation/roadmap.md#L169), [reserve no-fit branch:196](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L196).

### Current margin, eligibility and the previous reservation

Use the latest migration definitions: `20261019000000_preserve_margin_with_settlements.sql` replaces preview/reserve after the settlement migration and removes its obsolete reservation overload. Current preview and reserve read the saved account margin with a default of 10%, using `private.calculate_reservation_grams`. Saving settings itself updates account settings without resizing an existing reservation. [compatibility migration:1](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L1), [preview margin:39](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L39), [reserve margin:148](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L148), [formula:69](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L69), [settings write:87](../../../supabase/migrations/20261017000000_account_safety_margin.sql#L87).

The current eligibility predicate matches owner, canonical material and colour key, then checks recorded stock minus active reserved grams against the required reservation amount. The automatic ordering is available grams ascending, spool creation time ascending, spool identifier ascending. Manual selection still requires eligibility. Since the amount is constant across a print's candidates, ranking available grams yields the PRD's ranking by remaining grams after reservation. [candidate selection:180](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L180), [manual eligibility:203](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L203).

**Derived requirement:** evaluate candidates with the edited print's previous reservation excluded from the totals, or remove that reservation within the same transaction before selection. Otherwise the print competes with its own held stock. For an illustrative spool with 150 g recorded, no other reservations, and this print holding 88 g for an 80 g requirement at 10%, an eligible recalculation at 5% requires 84 g. Excluding its previous hold gives 150 g capacity and 66 g available afterward; using the current 62 g available would incorrectly reject that spool. This is a calculation from the named inputs, not an executed acceptance result. [PRD example:48](../../foundation/prd.md#L48), [margin behavior:61](../../foundation/prd.md#L61), [formula:77](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L77), [inventory totals:81](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L81).

Reservation rows already retain `selection_mode`, applied `margin_percent`, spool identity and creation time. The current print projection/DTO exposes reservation identity, spool identity and reserved grams, but omits selection mode and applied margin. Server-side selection can use the persisted row without expanding the browser DTO merely to recover manual intent. [reservation schema:7](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L7), [current projection:35](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L35), [DTO:29](../../../src/lib/prints.ts#L29).

### Request evidence, release and settlement compatibility

Successful initial reservations save request identity, print/spool identity, expected print version, selection mode, reservation identity, lifecycle state and the previewed gram amount. In the current reserve function, matching active replays return before rechecking the current print or margin; changed command parameters conflict, and terminal requests return `reservation_request_completed`. Recalculation must not accidentally turn an earlier reserve command into a different command or revive a released allocation. [request schema:40](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L40), [amount witness column:106](../../../supabase/migrations/20261017000000_account_safety_margin.sql#L106), [replay:115](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L115), [ledger insert:226](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L226).

Release targets the exact reservation and print identities, looks up private request evidence, and returns the spool identified by that evidence. It does not require a print version. Settlement additionally requires an active request row matching the current reservation's print and spool. Moving a public reservation without coordinating that evidence would break settlement and could report the wrong affected spool during release. [release:306](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L306), [settlement checks:356](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L356).

Reservation identity and age have observable consequences. Retaining an identity permits an already-issued release for that identity to release the resized allocation. Replacing it changes which allocation an old release can affect. Giving a replacement a new creation time changes its place in settlement's newest-first cancellation order; equal timestamps use reservation identity as the tie-breaker. These are design decisions to state explicitly, rather than incidental consequences of the chosen SQL operation. [release identity:313](../../../supabase/migrations/20261016000000_reserve_and_release_material.sql#L313), [settlement order:400](../../../supabase/migrations/20261018000000_settle_print_consumption.sql#L400), [PRD:121](../../foundation/prd.md#L121).

### API and outcome representation

`POST /api/prints/[id]/update` validates authentication, path identity, supported form type and edit fields including `expectedVersion`. Its success is HTTP 200 `{ print }`. The form validator rejects unexpected fields, so adding request identity or another edit command field requires a corresponding validator change. [update endpoint:24](../../../src/pages/api/prints/[id]/update.ts#L24), [success:63](../../../src/pages/api/prints/[id]/update.ts#L63), [form allowlist:172](../../../src/lib/print-validation.ts#L172).

`updatePrint` extracts the RPC's returned identity and separately reads `planned_prints`. A failed post-commit read is classified as a database failure; a successful read reflects the later read's state rather than a retained snapshot of the edit transaction. `PrintDto` can represent the final reserved/unreserved state, but that state alone cannot prove whether this edit removed a reservation or a subsequent command did. A feedback contract must distinguish a known successful unreserved edit from a rejected edit and an uncertain outcome. [helper:193](../../../src/lib/prints.ts#L193), [read helper:125](../../../src/lib/prints.ts#L125), [DTO reader:9](../../../src/lib/print-dto.ts#L9), [mutation failure guidance:172](../../../src/lib/print-response.ts#L172).

Current named update failures include `edit_conflict`, `print_settled`, `not_found`, and the temporary `reserved_print_edit_requires_cancellation`. Malformed/invalid form handling and sanitized database failure responses are already implemented. The form handles an edit 409 as a blocking conflict; its copy distinguishes the temporary reserved-edit restriction but otherwise uses generic stale-edit wording, including for `print_settled`. [API business failures:44](../../../src/pages/api/prints/[id]/update.ts#L44), [PrintForm.tsx:178](../../../src/components/prints/PrintForm.tsx#L178), [response mapping:183](../../../src/lib/print-response.ts#L183).

### Browser state, feedback and recovery

`PrintForm` submits its complete draft with the saved print version. Reserved requirement fields and their hints enforce the temporary cancellation-first policy. On conflict it retains the draft, disables resubmission, and asks for explicit discard consent before reading the latest print. [submission:101](../../../src/components/prints/PrintForm.tsx#L101), [conflict refresh:206](../../../src/components/prints/PrintForm.tsx#L206), [reserved controls:248](../../../src/components/prints/PrintForm.tsx#L248).

`PrintList` owns collection state and mutation handlers. `savePrint` replaces the returned print, announces a generic save, closes the editor and restores focus. Transport failures, unreadable success and HTTP 5xx responses set uncertainty guards; the ordinary refresh path reads the print collection and clears that guard after a successful read, with explicit form-discard handling. It does not read stock in this update recovery path or retain an exact edit command/receipt. [save callback:756](../../../src/components/prints/PrintList.tsx#L756), [uncertain handling:126](../../../src/components/prints/PrintForm.tsx#L126), [5xx handling:162](../../../src/components/prints/PrintForm.tsx#L162), [print refresh:786](../../../src/components/prints/PrintList.tsx#L786), [refresh reset:835](../../../src/components/prints/PrintList.tsx#L835).

Existing reservation preview recovery distinguishes retained manual selection, replaced manual selection, best-fit and no candidate. That is a useful local reference for wording/outcome handling, but the preview endpoint rejects an already-reserved print and is not an edit recalculation implementation. [preview selection handling:940](../../../src/components/prints/PrintList.tsx#L940), [already-reserved guard:32](../../../supabase/migrations/20261019000000_preserve_margin_with_settlements.sql#L32).

Settlement provides a stronger local recovery pattern: an RPC receipt parsed directly by the service, saved-receipt lookup, retained command identity, and reconciliation of print and stock collections. Its null-receipt handling keeps uncertainty when an earlier request may still commit. S-05 planning should choose the edit recovery guarantee explicitly; a durable edit ledger is an option, not an existing requirement inferred merely from settlement's implementation. [settlement service:46](../../../src/lib/settlements.ts#L46), [receipt endpoints:22](../../../src/pages/api/prints/[id]/settlement.ts#L22), [collection reconciliation:266](../../../src/components/prints/PrintList.tsx#L266), [pending result handling:386](../../../src/components/prints/PrintList.tsx#L386).

## Architecture Insights

The planning boundary spans the database edit operation, request bookkeeping, typed service/API outcome, and the owning print collection's feedback/recovery. Capacity must be evaluated after accounting for the old hold, using current canonical matching and the margin read under the owner lock. A valid no-fit outcome commits the print while releasing that hold. Existing release and settlement consumers constrain how a replacement is represented. These implications follow from the database, replay and UI paths above; they do not select an implementation design.

The inspected production source calls `updatePrint` from the update API route; browser success enters through `PrintForm.onSaved` and `PrintList.savePrint`. Dashboard presentation should use the shared design contract and keep collection state/API handlers in `src/components/prints/`, as specified in [AGENTS.md](../../../AGENTS.md). Stock displays must preserve the separate recorded/reserved/available meanings.
